The Phase 1 OpenAPI draft covers 150 operations: the 20 legacy `/Paginated` routes are merged into lists with `page`/`pageSize`, and the refresh token is not exposed (it happens server-side). All 168 legacy HTTP operations plus the WebSocket are mapped in `api/route-inventory.md`.

The executable contract is generated by the backend into `../../InfraOrgITApi/openapi/InfraOrgIt.Api.json` (OpenAPI 3.1.1, 190 operations) and CI fails on drift; `api/openapi.yaml` remains the Phase 1 domain draft.

## Status

Phase 8 completed on the technical perimeter — 2026-10-27. Documents aligned with the legacy `InfraOrgIt` repository (outside the workspace) and the `backlog.md`. D1–D10 closed; D7 = B (per-environment tightening). Phase 2 implemented auth BFF, identity and shell; Phase 3 inventory/catalog, Phase 4 topology/diagrams, Phase 5 remote management, Phase 6 admin/RBAC; Phase 7 importer and the database init scripts for the application; Phase 8 hardening, deploy, observability, backup and load test. Checklists in `domain/*` and `operations/*`; the rehearsal on representative legacy data is still open. The `v0.2.0` images were published to GHCR; image signing, SBOM and provenance are part of the current workflows.

No application code was copied: the documents describe the domain and the decisions, not the source code.
